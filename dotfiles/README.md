# dotfiles

## dotfiles の更新通知

対話型の pwsh / zsh / bash の起動時に、この dotfiles リポジトリの
`main` とその upstream をバックグラウンドで比較します。
`main` と upstream の設定が必要です。リモート名は `origin` に限定しません。

- PowerShell はジョブ管理機構を使わず、最小限の非同期プロセスで確認します。
  更新用ヘルパーは必要時だけ読み込み、プロンプトでは完了済みの結果だけを取得します。
- 通信は認証入力なし、最大10秒。失敗や履歴の分岐は一度だけ通知します。
- fast-forward 可能なら、次のプロンプト直前に `[main update available]` と
  `Update dotfiles main now? [y/N]` を表示します。入力中の行には割り込みません。
- `y` または `Y` と Enter で更新します。それ以外と Enter のみは辞退です。
  承認入力はセッションに一度だけ。辞退後も更新表示を残します。
- `dotfiles-update` はどのディレクトリからでも手動実行できます。
  シェル起動時に `dotfiles/cmd` を PATH に追加します。
- 手動実行または承認した更新では、Git の fetch と fast-forward 更新の出力を表示します。
  別ブランチ上の参照更新では変更前後のコミットを表示します。起動時の確認は無音です。
- `main` 上では未追跡ファイルを含む未コミット変更があれば更新を拒否します。
  別ブランチや detached HEAD では作業ツリーに触れず `main` の参照だけを更新します。
  別 worktree で `main` がチェックアウト中の場合は拒否します。
- 強制リセット、自動 stash、自動マージはしません。複数の更新コマンドは
  Git 共通ディレクトリ内の `dotfiles-update.lock` で排他制御します。
  強制終了でロックが残った場合は、更新処理が動いていないことを確認してから削除してください。
- シェルに登録された `dotfiles-update` 関数は、更新後に設定を再読み込みします。
  別ブランチ上では現在のブランチの設定を再読み込みするため、更新した `main` の設定は反映されません。
  子プロセスとして直接実行したコマンドは、親シェルの設定を再読み込みできません。
- 非対話型シェルでは起動時の確認と承認入力を行いません。

PowerShell 7 以降と、bash / zsh 環境では共通処理用の bash が必要です。
検証は `pwsh -NoProfile -File ./dotfiles/tests/update.ps1` で実行できます。
bash があれば共通シェル処理も一時リポジトリで検証します。
