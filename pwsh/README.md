# PowerShell

## 設定ファイルのシンボリックリンク

Git と VS Code のセットアップは、共通処理
[`Set-DotfilesSymbolicLink`](../setup_utils/pwsh.ps1) で設定ファイルをリンクします。
存在確認は内容ではなく、シンボリックリンクの種類と参照先で判定します。
正しいリンクが既にある場合、UAC は表示されません。

リンクの作成だけを別の PowerShell プロセスで管理者権限に昇格します。
親シェルやセットアップ全体は昇格しません。既存ファイル（ハードリンクを含む）は
同じディレクトリに `.dotfiles-backup-<ID>` 付きで退避します。
UAC をキャンセルした場合や作成に失敗した場合はエラーを報告し、
作成先が空なら既存ファイルを復元します。予期しない項目が作成先にある場合は
上書きせず、バックアップの場所を報告します。

## Unix 風プロセスコマンド

`bin` の `kill` と `pkill` は PowerShell 関数として読み込まれます。
`kill` は PID を指定し、`pkill` はプロセス名に対する正規表現で対象を選びます。

```powershell
kill 1234
kill -9 1234
kill -s TERM 1234
pkill '^python'
pkill -KILL '^python'
```

Windows は Linux のシグナルをサポートしないため、`TERM` は通常の `Stop-Process`、
`KILL` は `Stop-Process -Force` として処理します。対応シグナルは `TERM` と `KILL`
（`15` / `9`、`SIGTERM` / `SIGKILL` 表記を含む）のみです。
`pkill` の正規表現はプロセス名（拡張子を除く）に対して大文字小文字を区別し、
呼び出し元の PowerShell プロセスは対象から除外します。
Tab 補完では、`kill` に実行中プロセスの PID（プロセス名付き）、`pkill` に
プロセス名、`-s` / `--signal` の後に対応シグナルを候補表示します。

## ディスク使用量コマンド

`bin` の `df` と `du` は GNU Coreutils でよく使うオプションを PowerShell で提供し、
オプション、サイズ指定、パスを Tab 補完します。

`df` は Windows の利用可能なボリュームを表示します。`-h` / `-H`、`-k` / `-m`、
`-B SIZE`、`-T`、`-t TYPE`、`-x TYPE`、`--total` に対応します。`-a` と `-P` は
Windows のボリューム一覧では表示結果を変えません。

`du` はファイルの論理サイズを再帰集計し、`-a`、`-b`、`-B SIZE`、`-c`、`-d N`、
`-h` / `-H`、`-k` / `-m`、`-s`、`-S`、`-x`、`--exclude PATTERN` に対応します。
Windows では割当済みディスク容量やハードリンク数を取得せず、ディレクトリの
シンボリックリンク/ジャンクションは辿りません。`--apparent-size` は既定の集計と
同じ論理サイズを使います。これは GNU Coreutils の完全な互換実装ではありません。

## ファイル同期コマンド

[`bin/rsync.ps1`](bin/rsync.ps1) の `rsync` 関数から
[`rsync.py`](rsync.py) を呼び出します。ローカル間と SSH 経由のアップロード・
ダウンロードに対応し、接続先は Windows / Linux / macOS を想定しています。
本家 rsync の通信プロトコルとは互換性がありません。

### 必要な環境

- ローカル: `python` または `python3` として実行できる Python 3.10 以上。
- SSH 利用時: ローカルの `ssh` と、接続先の Python 3.10 以上。
  接続先では `python3`、`python` の順に起動を確認します。
- Python の追加パッケージ、接続先への本ツールの事前インストールは不要です。
  ワーカーコードを SSH の標準入力で渡し、メモリ上で実行します。
- SSH の鍵、エージェント、接続設定、ホスト鍵確認は既存の `ssh` に委ねます。
  Python の確認と転送に別の接続を使用するため、鍵認証の利用を推奨します。

### 使用例

```powershell
# 変更予定を確認してから、ディレクトリの中身を同期する
rsync -rtnv 'C:\work\project\' 'D:\backup\project'
rsync -rt --stats 'C:\work\project\' 'D:\backup\project'

# 既定でファイル名・進捗・サマリーを表示する。自動処理では -q で抑制できる
rsync -rtq 'C:\work\project\' 'D:\backup\project'

# SSH アップロード / ダウンロード
rsync -rtv --exclude '*.tmp' 'C:\work\project\' 'user@linux:/srv/project'
rsync -rtv 'user@linux:/srv/project/' 'C:\work\project'

# Windows 接続先。通常は SSH ログインユーザーのホームからの相対パスも使える
rsync -rtv 'C:\work\project\' 'user@windows:D:\backup\project'

# 接続先 Python のパスを指定。空白を含むパスも、引数全体を引用すれば使える
rsync -rtv --remote-python 'C:\Program Files\Python314\python.exe' `
    --remote-shell powershell 'C:\work\project\' 'user@windows:D:\backup\project'

# コピー元にないファイルも削除する場合は、必ず先に dry-run で対象を確認する
rsync -rtnv --delete 'C:\work\project\' 'D:\backup\project'
rsync -rtv --delete 'C:\work\project\' 'D:\backup\project'
```

コピー元ディレクトリの末尾に `\` / `/` がある場合は「中身」を同期します。
末尾区切りがなく、コピー先が既存ディレクトリなら、その下にコピー元の
ディレクトリ名を追加します。コピー先が存在しない場合は、その名前で作成します。
コピー元・コピー先はそれぞれ 1 つ指定します。
ワイルドカードによるコピー元の展開や、リモートパスのシェル変数展開は行いません。
`~` はそのパスを扱う側のユーザーホームに展開します。
ドライブ文字はローカルパスとして解釈するため、1 文字の SSH ホスト別名には
`user@h:path` のようにユーザー名を付けてください。IPv6 は `user@[::1]:path` 形式です。

### 対応オプション

| オプション | 動作 |
| --- | --- |
| `-r`, `--recursive` | ディレクトリを再帰同期。ディレクトリのコピー元には必須 |
| `-t`, `--times` | ファイル・ディレクトリの最終更新時刻を保持 |
| `-c`, `--checksum` | サイズと SHA-256 で内容を比較 |
| `-n`, `--dry-run` | 計画のみ表示。コピー先の作成・変更・削除は行わない |
| `-v`, `--verbose` | 処理段階・作成・転送・削除対象を表示。既定で有効 |
| `--progress` | ファイルごとのバイト数・割合・速度・残り時間を表示。既定で有効 |
| `--no-progress` | 進捗行だけを抑制。ファイル名と完了サマリーは表示 |
| `--no-verbose` | 処理段階とディレクトリ・削除対象の一覧を抑制。進捗は別指定 |
| `-q`, `--quiet` | 通常出力をすべて抑制。`-v`・`--progress`・`--stats` より優先。エラーは表示 |
| `-h`, `--human-readable` | サイズを `K` / `M` / `G` などの単位で表示（1000 倍単位） |
| `--stats` | ファイル数、作成・削除・転送数、総サイズ、実転送データ量、処理時間の詳細を追加 |
| `--delete` | 同期先ルートの内側で、コピー元にない項目を削除 |
| `--exclude PATTERN` | 大文字小文字を区別して除外。繰り返し指定可能 |
| `--modify-window SECONDS` | 更新時刻の比較許容差。既定は 1 秒、厳密比較は `0` |
| `--port PORT` | SSH ポート |
| `--remote-python EXECUTABLE` | 接続先 Python のコマンド名または実行ファイルパス |
| `--remote-shell auto\|sh\|cmd\|powershell` | SSH ログインシェル。既定は `auto` |
| `--log-level LEVEL` | `DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL`。既定は `INFO` |
| `--help` | ヘルプ。`-h` は本家に合わせてサイズの可読表示に使用 |

### 実行中の表示

本家 rsync と異なり、このコマンドは**既定で `-v --progress` 相当の表示を有効**にします。
SSH 接続開始、ファイル一覧の走査開始、転送対象のファイル名を表示し、
コピー中は本家に近い形式の進捗、終了時にはサマリーを表示します。

```text
connecting to user@host ...
building file list ...
done
./
example.dat
              0   0%    0.00B/s   --:--:--
      1,048,576  50%    1.00MB/s    0:00:01
      2,097,152 100%    1.00MB/s    0:00:02 (xfr#1, to-chk=0/1)
verifying source ...

sent ... bytes  received ... bytes  ... bytes/sec
total size is ...  speedup is ...
```

進捗の速度はそのファイルの転送開始からの平均、途中の時間欄は推定残り時間です。
`100%` は転送先でチェックサム検証・置換が成功した後にだけ表示し、その行の時間欄は
ファイルの処理所要時間です。`xfr#` は転送済みファイル数、
`to-chk` はソート済みの通常ファイル一覧で後続にあるファイル数／全通常ファイル数です。
初期の速度が未確定な間は残り時間を `--:--:--` とします。

端末出力は同じ行を更新し、途中の進捗更新は最大 1 秒に 1 回です。
PowerShell のパイプなど端末でない出力先では、同じ行を書き換えず改行して出力します。
開始・完了の進捗は間引かず、通常出力は即座にフラッシュします。
ファイル名内の改行などの制御文字は `\#012` のようにエスケープします。
変更なしの場合も、転送量 `0` の完了サマリーを表示します。

SSH の `sent` / `received` はワーカーコードと JSON/Base64 プロトコルの実バイト数です。
SSH 暗号化・認証のオーバーヘッドは含まず、本家の通信量と同じ値にはなりません。
`speedup` は総ファイルサイズをこれらの合計バイト数で割った値です。
ローカル同期では通信量を装わず、`transferred ... bytes` と実ファイルデータ量を表示します。
`--stats` の `Literal data` は実際に転送したファイル内容のバイト数、
`Matched data` はブロック差分転送を行わないため常に `0` です。
dry-run は予定のファイル名・転送サイズを表示し、進捗の `100%` は表示しません。
実転送量は `0` のまま、末尾に `(DRY RUN)` を付けます。

以前ヘルプを表示していた `-h` は、本家に合わせて `--human-readable` に変更しました。
ヘルプには `--help` を使ってください。同期方式や転送対象の判定は変更していません。

既定の差分判定はファイルサイズと最終更新時刻です。
同じサイズ・許容差内の更新時刻で内容だけが違う場合は、`--checksum` を使ってください。
`--modify-window` は保存先ファイルシステムの時刻精度に応じて調整できます。

除外は Python `fnmatch` 形式の `*`、`?`、`[abc]` に対応します。
区切りなしのパターンは各項目名、`/` を含むパターンは同期ルートからの
相対パスに照合します。先頭 `/` はルート基準、末尾 `/` はディレクトリ限定です。
相対パス内の区切りには `/` を使い、`*` は区切りにも一致します。
本家 rsync のフィルタ規則や `**` の特別な意味は実装していません。
除外ディレクトリは走査せず、コピー先の除外項目とその祖先は削除しません。

通常の Python コマンド名は `sh` / `cmd` / PowerShell 共通の形式で起動します。
`--remote-python` に引用が必要なパスを指定した場合、`auto` ではログインシェルを
確認します。判別不能な場合はエラーとなるので、`--remote-shell` を指定してください。
実行ファイルパスにシェル展開文字を含めたり、Python の起動オプションを
`--remote-python` に埋め込んだりすることはできません。

### 安全性と制限

- 変更のある**ファイル全体**を転送します。ブロック差分転送・圧縮・途中再開は未対応です。
  通信は最大 1 MiB のデータを Base64 化した JSON メッセージ単位で行います。
  メモリ使用量はファイル全体のサイズには比例しませんが、ファイル一覧はメモリに保持します。
- ファイル単位で同じディレクトリの一時ファイルへ書き、SHA-256 を検証してから置換します。
  通常のエラー・切断時は一時ファイルを削除します。強制終了・電源断では残る場合があります。
  複数ファイルをまとめたトランザクションではなく、既に完了した転送は巻き戻しません。
- コピー元の走査・転送で失敗した場合、削除処理には進みません。
  削除直前にもコピー元全体を再検証します。ただしスナップショットや排他ロックは
  取得しないため、同期中にコピー元・コピー先を別プロセスで変更しないでください。
- シンボリックリンク、ジャンクション、その他の reparse point と特殊ファイルは拒否します。
  同期ルートの祖先にあるリンクも拒否します。ファイル／ディレクトリの型の置換は行いません。
- ローカルのコピー元・コピー先の包含関係は拒否します。
  SSH 経由で同じ実体を指す場合は検出できないので、重複する場所を指定しないでください。
- Windows で表現できない名前や、コピー元内の大文字小文字の衝突は転送前に拒否します。
  Windows 側の既存項目との大文字小文字だけの違いは同じ同期先として扱います。
- 所有者、グループ、ACL、拡張属性、ハードリンク関係、実行権限のコピーは行いません。
  既存ファイルの置換時は従来のモードを引き継ぎ、新規ファイルは一時ファイルの
  制限された権限を使います。POSIX の実行ファイルの配布には別途権限設定が必要です。
- `-a` / `-z` / `-e` などの未対応オプションはエラーにします。
  SSH デーモンの rsync モード、リモート間転送も未対応です。
- 終了コードは成功 `0`、同期・接続エラー `1`、引数エラー `2`、中断 `130`。
  PowerShell では `$LASTEXITCODE` で確認できます。

### 同期コマンドの検証

```powershell
python -B -m unittest discover -s .\pwsh\tests -p test_rsync.py -v
pwsh -NoProfile -File .\pwsh\tests\rsync.ps1
```

一時ディレクトリでローカル同期と Python ワーカーの実プロセス間通信を検証します。
SSH コマンドの起動部分だけを差し替えるため、SSH サーバーや鍵は不要です。
Windows では `cmd` / PowerShell 経由のワーカー起動も検証します。
リンクを作成する権限がない環境では、シンボリックリンクのテストだけをスキップします。
実際の SSH 接続先、認証、Linux/macOS のファイルシステムとの組み合わせは、
利用環境で別途検証してください。

## Documents

[`create_document_symlink.ps1`](create_document_symlink.ps1) を手動実行すると、
`$HOME\Documents` から Windows の Documents フォルダーへのリンクを作成します。
Windows 側の Documents は事前に OneDrive など別の場所へ設定してください。
旧 `create_document_hardlink.ps1` はこの名前に変更しました。
リポジトリ内に旧スクリプトの呼び出し元はありません。

同じ参照先の既存ジャンクションはシンボリックリンクに置き換え、
成功後に旧ジャンクションだけを削除します。通常のディレクトリや
異なる参照先のディレクトリリンクは自動置換しません。
